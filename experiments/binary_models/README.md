## General Data Preprocessing Flow

All models need to complete **unified basic data preprocessing** first (based on the original .c source code in the data directory). Among them, **only CodeBERT, VulCNN, and VulRoberta models need to use models/merge_pkl.py to merge PKL files**. The Devign model does not require merging; it only needs to execute its own specific preprocessing steps. All derived data (PKL, graphs, word2vec models) are automatically generated under the models directory.

### Step 1: Prepare Original Data

Place the original .c source code files to be processed into the standardized directory (no need to modify the directory structure; only initial .c files are stored in the outer data directory):

```plain text
/home/VulInject/experiments/binary_models/data/sub_original_dataset/
```

### Step 2: Generate Labeled Basic PKL Dataset

```bash
cd /home/VulInject/experiments/binary_models/models
```

Run the generate_ori_pkl_vulinject function in models/generate_pkl.py to read the original .c code in the data directory, process it, and add vulnerability labels (0 for no vulnerability, 1 for vulnerability). This will generate a basic PKL dataset common to all models (automatically saved under the models/pkl directory). Note the processing of the val label generated by generate_ori_pkl_vulinject, which is distinguished by different file names.

**Note**: Before running, confirm that the label logic is consistent with the dataset to avoid abnormal experimental results caused by label errors.

### Step 3: Train Word2vec Model (Required for Text/Graph Models)

Run the models/word2vec.py script to train the word2vec model based on the current dataset. The model will be automatically saved to the following directory for subsequent model calls (under the models directory, not the outer data directory):

```plain text
models/word2vec_model/
```

### Step 4: PKL File Merging (Required Only for CodeBERT, VulCNN, VulRoberta!)

The training/test sets of CodeBERT, VulCNN, and VulRoberta models need to be merged using `models/merge_pkl.py`. The script automatically reads the basic PKL files under the models/pkl directory and completes the merging.

#### PKL Merging Reproduction Steps (Execute Directly)

1. Open `models/merge_pkl.py` and find the `if __name__ == "__main__":` code block;

2. According to the target model, confirm that the `target_middle_dirs` list contains the corresponding directory (no need to modify the default value, which is already adapted for CodeBERT, VulCNN, and VulRoberta);

3. Ensure that the paths in the `input_files` list are consistent with the paths of the basic PKL files generated in Step 2 (PKL files are stored under the models/pkl directory by default);

4. Run the script directly based on the project root directory: `python models/merge_pkl.py`

5. After the script runs, `train_new.pkl` (the merged dataset) will be automatically generated. No additional operations are required; it can be directly used for subsequent model training.

6. Rename the test set to obtain test_new.pkl.

#### Notes

- Before merging, ensure that all input PKL files are in DataFrame format and contain the val label column;

- PKL files of different models need to be placed in the corresponding intermediate directories (e.g., VulCNN's PKL files are placed in `./models/pkl/vulcnn/sub_original_dataset/`, and CodeBERT's PKL files are placed in `./models/pkl/sub_original_dataset/`) to avoid path errors.

## Model-Specific Training Flows

After completing the general data preprocessing (Steps 1-4, including PKL merging), execute the corresponding specific preprocessing, training, and evaluation steps according to the model type. (Independent test scripts are used for evaluation; no need to modify models/main.py.) All flows are executed based on the project root directory. The core logic of all models is under models/model/, and training is called via models/main.py.

### 1. CodeBERT (Simplest, No Graph/Image Processing Required)

A text-based vulnerability detection model that does not require additional graph or image processing. Training can be started after completing general preprocessing (including PKL merging).

#### Preprocessing

1. Complete **general data preprocessing (Steps 1-4)**;

2. PKL merging (required): Open `models/merge_pkl.py`, confirm that `target_middle_dirs` contains `''` (no intermediate directory), run the script `python models/merge_pkl.py`, and `train_new.pkl` will be automatically generated.

#### Training

1. Modify models/main.py: In the main() function, uncomment the train_code_bert function, adjust hyperparameters (epochs, learning rate, batch size, etc.) as needed, and configure the path of the merged PKL file (train_new.pkl); the core is to call the core logic in models/model/CodeBert.py.

2. Execute the training command: `python models/main.py`

#### Evaluation

1. Use the independent test script `models/codebert_test.py`;

2. Open `models/codebert_test.py` and modify only two key paths:
        

    - Pretrained model path;

    - Test set path.

3. Execute the evaluation command to automatically calculate metrics and save error samples: `python models/codebert_test.py`

### 2. VulRoberta

#### Preprocessing

1. Complete **general data preprocessing (Steps 1-3)**;

2. Run the VulRoberta-specific dataset processing script: Based on the project root directory, execute the command `python models/generate_vulberta_data.py` (full path: /home/VulInject_copy/experiments/binary_models/models/generate_vulberta_data.py). No other parameters need to be modified; it automatically adapts to the merged train_new.pkl.

3. PKL merging (required): Open `models/merge_pkl.py`, confirm that `target_middle_dirs` contains `'vulroberta'`, run the script `python models/merge_pkl.py`, and `train_new.pkl` will be automatically generated.

#### Training

1. Modify models/main.py: In the main() function, uncomment the train_vulroberta function, adjust hyperparameters as needed, and configure the path of the merged PKL file (train_new.pkl); the core is to call the core logic in models/model/VulRoberta.py.

2. Default optimal initial hyperparameters:
        

    - evaluate = False (indicating training mode)

3. Execute the training command: `python models/main.py`

#### Evaluation

1. Use the independent test script `models/vulberta_test.py` directly;

2. Open `models/vulberta_test.py` and modify only two key paths:
        

    - Pretrained model path;

    - Test set path.

### 3. VulCNN (Requires Image Features + Graph Preprocessing)

An image feature-based vulnerability detection model. After completing general preprocessing (including PKL merging), additional graph generation and image feature conversion steps are required before starting training/evaluation.

#### Preprocessing (After General Preprocessing)

1. Complete **general data preprocessing (Steps 1-3)**;

2. Run the graph generation script: `python models/joern_graph_gen.py` (generates source code graph data via the Joern tool);

3. Run the image feature conversion script: `python models/ImageGeneration.py` (converts graph data to image features required by VulCNN);

4. Then run the generate_vulcnn_dataframe(dataset_name) function in models/generate_pkl.py (note the dic.append syntax to avoid value error);

5. Then use models/merge_pkl.py to merge the training set and test set (the flow is the same as Step 4).

#### Training

1. Modify models/main.py: In the main() function, uncomment the train_vulcnn function; the core is to call the core logic in models/model/VulCNN.py.

2. Execute the training command: `python models/main.py`

#### Evaluation

1. Use the independent test script `models/vulcnn_test.py` directly;

2. Open `models/vulcnn_test.py` and modify only two key paths:
        

    - Pretrained model path;

    - Test set path.

3. Execute the evaluation command to automatically calculate metrics and save error samples: `python models/vulcnn_test.py`

### 4. Devign (Graph-Based Model, No PKL Merging Required)

A Program Dependency Graph (PDG)-based vulnerability detection model. It does not require PKL merging steps. After completing general preprocessing, execute its own specific graph preprocessing to start training/evaluation.

#### Preprocessing (After General Preprocessing)

1. Complete **general data preprocessing (Steps 1-3)** (no need to execute Step 4 PKL merging);

2. Run the graph generation script: `python models/joern_graph_gen.py` (generates source code PDG graph data via the Joern tool);

3. Modify line 153 of the models/joern_to_devign.py script to adapt to the current dataset path, then run the script: `python models/joern_to_devign.py` (converts Joern graphs to the input format supported by Devign);

4. Run the graph merging script: `python models/devign_pdg_new/merge.py` (the script path is consistent with the project structure; it merges the converted JSON graph files into train_0.txt and test_0.txt);

5. Run the Devign-specific dataset generation function: Modify main.py, call the devign_prepare(file, 0) function (replace file with the dataset name, such as primevul_train), and run main.py once to generate the specific binary dataset.

#### Training

1. Modify models/main.py: In the main() function, uncomment the train_devign function and adjust hyperparameters as needed;

2. Execute the training command:`python models/main.py`

#### Evaluation

1. Use the independent test script `models/devign_test.py` directly;

2. Open`models/devign_test.py` and modify only two key paths: the model path and the test set path (i.e., test_0.txt generated by preprocessing);

3. Execute the evaluation command to automatically calculate metrics and save error samples: `python models/devign_test.py`
